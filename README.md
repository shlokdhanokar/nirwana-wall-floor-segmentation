## Approach in one paragraph
Wall vs. floor is a **layout** decision, not an appearance one. The same beige texture is floor at the bottom of the frame and wall behind the sofa, and a white wall, white ceiling and white window can be colour-identical. So the problem is set up as 3-class dense labelling (*other / wall / floor*) and solved with **WallFloorNet**, a 3.3 M-parameter encoder-decoder. It combines a MobileNetV3-Large encoder with my own global-context FPN decoder, **trained from scratch for this task** on ~9.2k interior scenes filtered out of ADE20K (wall → wall, floor + rug → floor). No pre-trained or fine-tuned segmentation model is used. The network runs at ~384 px. A **fast guided filter** then snaps its predictions to real image edges at full resolution, and connected-component cleanup removes specks. A training-free **classical baseline** (LSD vanishing-point horizon + GrabCut) was built first. Its failures on colour-ambiguous walls are the reason a learned model was needed, and it is kept as a comparison.

```
image ─► resize (short side 384) ─► WallFloorNet ─► probs ─► fast guided filter (full-res guide) ─► argmax ─► CC cleanup ─► wall / floor masks
```

## Results
Quality on the **held-out ADE20K interior validation split** (922 images) and on the reference image shipped with the task. Latency is end-to-end on the 3558×2160 reference photo, on CPU.

See [`results/metrics.md`](results/metrics.md) (generated by `scripts/evaluate.py`) and the qualitative worst/median/best panels in [`results/gallery/`](results/gallery/). Full-resolution masks for the sample image are in [`results/samples/`](results/samples/).

## Performance optimisation
| Change | Effect (measured on the 3558×2160 reference photo, 4 CPU threads) |
|---|---|
| Network at short side 384, full resolution recovered by a guided filter instead of a full-res forward pass | ~50× fewer network FLOPs than running at full resolution |
| Guided filter applied through its **linear decision functions**: argmax(q_other, q_wall, q_floor) reduces to signs of three functions linear in the guide, so the per-pixel coefficients are combined at low resolution and full resolution only sees single-channel multiply-add + compare | refine + cleanup stage ~0.9 s → ~0.26 s; whole pipeline ~1.3 s → ~0.35 s |
| Decisions capped at 2048 px long side, then the final uint8 label map is nearest-upsampled (edge error ≤ 1.7 px on 12 MP) | further ~40 % on very large photos |
| Connected-component cleanup on a max-pooled 1024 px copy (conservative by construction) | ~150 ms → ~30 ms per mask |
| ONNX Runtime (graph fusion) | network ~1.5–2× faster than eager PyTorch on CPU |
| INT8 static quantisation (QDQ, per-channel, percentile calibration) | 13.3 MB → 3.8 MB; accuracy impact reported honestly in the metrics table |
| Training-side: thread-pool data loader, augmentation as a single affine warp plus uint8 LUT colour jitter, normalisation on the GPU | ~2× data-pipeline throughput (46 → ~100 img/s) |

## Repository layout
```
wallfloor/            the package
  labels.py           3-class label space, ADE20K remap, interior-scene filter
  prepare.py          ADE20K → interior subset cache (torch-free, multiprocess)
  data.py             training dataset + augmentations, thread-pool loader
  model.py            WallFloorNet (encoder + global-context FPN decoder)
  train.py            training loop (CE + soft Dice, AMP, cosine LR)
  refine.py           fast guided filter + linear-decision refinement, CC cleanup
  infer.py            WallFloorSegmenter: image → masks (PyTorch or ONNX backends)
  classical.py        training-free baseline (LSD horizon + GrabCut)
  metrics.py          IoU, boundary F-score
  export.py           ONNX export + INT8 static quantisation
  viz.py              overlays and panels
scripts/
  evaluate.py         every pipeline variant: quality (val + reference) and CPU latency
  make_gallery.py     worst/median/best qualitative panels + sample masks
  build_notebook.py   generates both notebooks (numbers are embedded from results/)
samples/              reference image + its ground-truth masks
weights/              trained model (.pt), ONNX FP32 and INT8 models, training history
results/              metrics, gallery, sample output masks
docs/discussion.md    technical discussion
```

## Run locally
```bash
pip install -r requirements.txt
python -m wallfloor.infer --weights weights/wallfloor_mbv3.onnx --out results/mine path/to/room.jpg
```
```python
from wallfloor.infer import WallFloorSegmenter, load_rgb
seg = WallFloorSegmenter("weights/wallfloor_mbv3.onnx")   # or .pt; tta=True for a little more accuracy
out = seg(load_rgb("room.jpg"))                          # out["wall"], out["floor"]: HxW bool
```

## Reproduce training
```bash
# ADE20K SceneParsing: http://data.csail.mit.edu/places/ADEchallenge/ADEChallengeData2016.zip → data/
python -m wallfloor.prepare --ade-root data/ADEChallengeData2016 --out data/cache
python -m wallfloor.train   --cache data/cache --out weights/wallfloor_mbv3.pt --epochs 30
python -m wallfloor.export  --weights weights/wallfloor_mbv3.pt
python scripts/evaluate.py && python scripts/make_gallery.py && python scripts/build_notebook.py
```

## Constraint compliance & disclosures
* **No pre-trained or fine-tuned segmentation model.** No segmentation weights of any kind are used. The segmentation network, losses and training were developed and trained here.
* **Encoder initialisation:** torchvision MobileNetV3-Large **ImageNet-1k classification** weights (an image classifier). `--no-pretrained-encoder` trains it from random initialisation instead.
* **Dataset:** ADE20K SceneParsing (MIT CSAIL; Zhou et al., CVPR 2017), used only for its wall/floor/rug labels on interior scenes.
* **Libraries:** PyTorch, torchvision, OpenCV, NumPy, ONNX, ONNX Runtime, Matplotlib, pandas.
* **No external APIs or cloud services** are used for segmentation. Everything runs locally.
* **AI tools:** Claude Code (Anthropic) was used as a coding assistant during development.
